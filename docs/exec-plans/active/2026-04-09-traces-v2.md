## Purpose / Big picture

After this work, users can navigate to `/sessions/:id/traces-v2` and see session events rendered as a collapsible tree with synchronized timeline bars — making the causal chain (user prompt → assistant → tool calls → results) visually explicit and navigable.

Verification: open any session detail page, click the "Traces V2" tab, see a tree of spans with timeline bars. Expand/collapse nodes. Click a span to see detail metadata.

## Decision Log

- Decision: Build semantic hierarchy from entry sequence, not from parentId chain
  Rationale: parentId is a linear chain (each entry → previous entry), not semantic nesting. A useful tree requires grouping by conversation turn and nesting content blocks under their assistant message.
  Date/Author: 2026-04-09

- Decision: Start without gap compression
  Rationale: Real time makes hierarchy timing clearer. Compression can be added later if long idle sessions make the view hard to read.
  Date/Author: 2026-04-09

- Decision: Synchronized scroll via single container with grid rows
  Rationale: The tree and timeline must scroll together. Rendering both in the same scroll container (each row = grid with tree cell + timeline cell) avoids dual-scroll synchronization complexity.
  Date/Author: 2026-04-09

### Data model recap

Session JSONL entries have a `parentId` that forms a linear chain (each entry points to the previous one). The hierarchy for the tree view is **synthesized** by the transform:

- User messages become root-level spans (one per conversation turn)
- Assistant messages become children of their preceding user message
- Content blocks (text, thinking, tool calls) become children of the assistant
- Tool results are matched to tool calls via `toolCallId` and become their children
- Metadata entries (model_change, session_info, etc.) attach at root level

## Plan of work

### Milestone 1: Types and transform

Define the `SpanNode` type and build `build_span_tree()` that converts `SessionEntry[]` into a tree of `SpanNode`s with timing.

**New files:**
- `src/components/traces-v2/types.ts`
- `src/components/traces-v2/trace-v2-transform.ts`

**SpanNode type:**
```
SpanNode {
  id: string
  label: string
  kind: "user" | "assistant" | "text" | "thinking" | "tool_call" | "tool_result" | "metadata" | "bash" | "custom"
  start_ms: number
  end_ms: number
  subtree_start_ms: number  // min(self.start, children.subtree_start)
  subtree_end_ms: number    // max(self.end, children.subtree_end)
  duration_ms: number       // end_ms - start_ms
  subtree_duration_ms: number
  color: string
  is_error: boolean
  depth: number
  children: SpanNode[]
  entry: SessionEntry
  content_index?: number    // for assistant content blocks
  result_entry?: SessionEntry  // for paired tool calls
}
```

**SpanTree type:**
```
SpanTree {
  roots: SpanNode[]
  total_duration_ms: number
  session_start_iso: string
  stats: { event_count, tool_count, error_count, model }
}
```

**Transform algorithm (`build_span_tree`):**

1. Parse timestamps relative to session start (same as v1)
2. Walk entries sequentially, grouping into conversation turns:
   - On `user` message → push new root span, set as "current turn"
   - On `assistant` message → create span, attach as child of current turn. This becomes "current assistant"
   - For each assistant content block → create child span under current assistant
   - On `toolResult` → find matching tool call child (by `toolCallId`) and attach result as its child; extend tool call end_ms
   - On `bashExecution` → treat like tool result
   - On metadata entries (model_change, session_info, etc.) → attach at root level
3. Compute subtree timing bottom-up: leaf nodes have subtree = self, parent subtree = union of children
4. Compute depth for each node

### Milestone 2: Core tree + timeline rendering

Build the visual components that render the span tree.

**New files:**
- `src/components/traces-v2/traces-v2-view.tsx` — main container
- `src/components/traces-v2/span-row.tsx` — single row (tree cell + timeline cell)
- `src/components/traces-v2/span-tree.tsx` — tree column content for a row
- `src/components/traces-v2/span-bar.tsx` — timeline bar for a row
- `src/components/traces-v2/timeline-ruler.tsx` — time axis header

**Layout:**
```
┌─────────────────────────────────────────────────────┐
│ Stats bar: span count, expand/collapse all          │
├──────────────────┬──────────────────────────────────┤
│ Service & Op     │ 0ms    12ms    25ms    38ms      │  ← ruler
├──────────────────┼──────────────────────────────────┤
│ ▾ User prompt    │              ██████████ 51ms     │  ← row
│   ▾ Assistant    │              █████████  49ms     │
│     TEXT         │              ██  2ms              │
│     THINKING     │                ████ 5ms          │
│     ▾ tool: Read │                    ██████ 12ms   │
│       result     │                      ████ 8ms    │
│   ...            │                                  │
└──────────────────┴──────────────────────────────────┘
```

The main container uses a single vertical scroll container. Each row is a CSS grid row with two columns: tree cell (fixed/resizable width) and timeline cell (flex-1).

The tree/timeline column split uses `ResizablePanelGroup` with `direction="horizontal"`.

**span-row.tsx**: Renders one row — receives the `SpanNode`, expanded state, and callbacks. Contains:
- Left: indented label with expand/collapse chevron (if has children), icon, label text, duration
- Right: positioned bar + duration label

**span-bar.tsx**: A `<div>` with `position: absolute`, `left` and `width` as percentages of total_duration_ms. Color from node's color variable. Duration text positioned to the left of the bar.

**timeline-ruler.tsx**: Time tick marks at regular intervals across the top of the timeline column.

### Milestone 3: Expand/collapse behavior

Add state management for which nodes are expanded/collapsed.

State: `Set<string>` of expanded node IDs (default: root nodes expanded, everything else collapsed — or all expanded by default, TBD).

When a node is collapsed:
- Its children are excluded from the visible row list
- The node's bar uses `subtree_start_ms` / `subtree_end_ms` for position and width
- The duration label shows `subtree_duration_ms`

Flatten function: walk the tree depth-first, skip children of collapsed nodes, produce a flat `VisibleRow[]` array with computed depth for rendering.

Controls:
- Chevron on each expandable row toggles that node
- "Expand all" / "Collapse all" buttons in the header

### Milestone 4: Detail panel

When a span row is clicked, show a detail panel between the header and the tree (like Jaeger's inline detail — it pushes content down).

**New file:** `src/components/traces-v2/span-detail.tsx`

Content:
- Span label, kind badge, duration, start time offset from session start
- Entry type and role
- For assistant text: truncated text preview
- For thinking: truncated thinking preview
- For tool calls: tool name, arguments (formatted JSON)
- For tool results: result content, error status
- For bash: command, exit code, truncated output
- Token usage (if assistant message with usage data)
- Entry ID for reference
- Close button
